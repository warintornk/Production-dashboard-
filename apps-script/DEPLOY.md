# Apps Script ฉบับแก้ไขจากโค้ดปัจจุบัน (ไฟล์ล่าสุด)

**ฉบับนี้แทนที่ Apps Script ที่เตรียมจากไฟล์เก่าซึ่งผู้ใช้แจ้งว่าส่งผิดแล้ว** ใช้ `Code.gs` ล่าสุดบน branch `fix/production-history-hours` เท่านั้น

ต้นฉบับที่ใช้คือโค้ดปัจจุบัน 6,775 บรรทัดที่ผู้ใช้ส่งครั้งล่าสุด คง CONFIG, Router_, การตรวจสิทธิ์, doGet/doPost, POST actions, cache, /version, เมนู และ utility เดิมไว้ การตั้งค่า Spreadsheet และ token ยังคงใช้ bound spreadsheet / Script Properties ตามต้นฉบับ ไม่มีการเปลี่ยน Spreadsheet ID หรือคีย์

## ปัญหาที่พบในโค้ดปัจจุบัน

`_buildFullPayload` ค้นข้อมูลย้อนหลังใน `Production History` ที่ใช้เก็บข้อมูลนำเข้าจากแดชบอร์ด แต่ไม่อ่าน `History (Prepare)` / `History (Assembly)` ที่ใช้เก็บประวัติรายวันในไฟล์จริง หากไม่พบข้อมูลใน Production History จะนำ Daily Record มาแสดงแทน แม้เป็นคนละเดือน

## การแก้ไข

- คงลำดับความสำคัญของ Production History เดิม แล้วค้น History รายห้องเพิ่ม
- อ่าน History เป็นชุดจากบล็อกแถว 42 เป็นต้นไป ไม่อ่านซ้ำจากพื้นที่แสดงเดือนที่เลือกแถว 9–39 และไม่เขียนชีตระหว่างอ่าน
- ส่งข้อมูลหลายเดือนผ่าน `productionDailyHistory` ให้หน้าเว็บแสดงรายเดือนและรายวันได้
- ถ้าไม่พบเดือนที่เลือก จะคืน rows ว่างพร้อมคำเตือน แทนข้อมูลผิดเดือน
- รองรับหัวเดือนแบบข้อความไทยที่มี ▶ และเซลล์ Date โดยใช้ timezone เดิมของระบบ
- ตรวจปีของบล็อกก่อนอ่าน และใช้ column mapping ของ archive โดยตรง ไม่อิงชื่อ header ของ Daily Record ที่อาจต่างกัน
- ป้องกันการเขียนทับบล็อกปีเก่าได้แม้หัวบล็อกเป็น Date
- หน้าเว็บใช้ปี/เดือนของข้อมูลจริง คงความละเอียดของชั่วโมง และเปลี่ยน daily drill-down ตามตัวเลือกเดือนด้านบน

## ขั้นตอนที่ต้องทำด้วยบัญชี Google เจ้าของระบบ

1. เปิด Apps Script โปรเจกต์ Web app ที่ใช้งานอยู่ สำรอง source ปัจจุบันไว้
2. ถ้าโปรเจกต์ใช้ไฟล์รวมเดียวตามที่ส่งมา ให้แทนที่เนื้อหาไฟล์นั้นด้วย `Code.gs` ฉบับล่าสุดแล้วบันทึก อย่าเพิ่มทั้งไฟล์เข้าโปรเจกต์ที่แยกโมดูลและมี CONFIG/Router_/doGet อยู่แล้ว เพราะจะเกิดชื่อซ้ำ
3. Deploy → Manage deployments → เลือก Web app เดิม → Edit → Version: New version → Deploy คง URL เดิมและค่าการเข้าถึงเดิม ไม่ต้องติดตั้ง config ใหม่หรือเปลี่ยน token
4. ใช้หน้าเว็บ `index.html` ฉบับแก้ไข กดรีเฟรช แล้วเลือก Prepare / ก.ย. 2026 / รายวัน วันที่ 1 ต้องเห็น Input 209.8 และ Output 150.9 ชั่วโมง ลอง ก.ค. และ Assembly เพิ่ม

ไม่ต้องกดบันทึก History เพื่อทดสอบการอ่าน การ Deploy ผ่าน Google และการรวม branch หน้าเว็บเข้า main ยังเป็นคนละขั้นตอน ไฟล์บน branch ไม่ได้เปลี่ยนเว็บออนไลน์เอง

## หลักฐานการทดสอบ

ผ่านการทดสอบ Apps Script ใน Node VM และ browser integration ด้วยข้อมูลจำลองและข้อมูลจาก Excel จริง ครอบคลุมหัว Date/ข้อความ, timezone, กันข้อมูลข้ามปี, แถวว่าง/ศูนย์, ลำดับแหล่งข้อมูล, การอ่านเมื่อไม่มี Daily Record sheet, ไม่อ่าน display area ซ้ำ, และยืนยันว่าไม่มีการเขียนชีตระหว่างทดสอบ การทดสอบ browser ใช้ payload จาก `_buildFullPayload` ฉบับปัจจุบันไปแสดงรายเดือน/รายวันและสลับเดือนจริงในหน้าเว็บ

เปรียบเทียบกับ source ปัจจุบันแล้ว CONFIG, Router_ และ doPost ไม่เปลี่ยน ไม่ได้ตรวจโทเคน/สิทธิ์บน Google จริงหรือเรียก Web app ที่ Deploy อยู่ จึงยังไม่อ้างว่าระบบออนไลน์แก้แล้ว
